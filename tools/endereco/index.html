Gerador de Endereço

Gere endereços fictícios do Brasil, EUA, Portugal, Espanha e Reino Unido para testes de software. Cidades e estados são reais; logradouro, número e código postal seguem o formato do país mas não são reais.

Aviso: os endereços gerados são fictícios e destinados exclusivamente a testes de software. Cidades e estados/regiões são reais; logradouro, número e código postal não correspondem a nenhum endereço real. Os códigos postais seguem apenas o formato do país — não são verificados em nenhuma base oficial. Não use esses dados para entregas, cadastros ou correspondência real.

Gerar endereço

Formatos de endereço por país

Cada país tem uma convenção própria para estruturar endereços postais. Esta ferramenta respeita o formato de cada país nos dados gerados:

Brasil

O endereço brasileiro segue o padrão: Tipo de logradouro + nome, número — complemento (opcional) na primeira linha, bairro na segunda, cidade e UF na terceira e CEP (8 dígitos, formato NNNNN-NNN) na quarta. O CEP é gerenciado pelos Correios e seu primeiro dígito indica a macro-região do país. Esta ferramenta respeita essa divisão regional ao gerar o CEP — o primeiro dígito é sempre coerente com o estado.

Exemplo de saída: Rua das Flores, 42 — Apto 101 / Jardim América / São Paulo — SP / CEP: 01310-450

Estados Unidos

O endereço americano segue o padrão: número + nome da rua na primeira linha, cidade, sigla do estado + ZIP Code na segunda. O ZIP Code tem 5 dígitos (formato NNNNN) e é gerenciado pelo USPS. Nesta ferramenta, o ZIP gerado segue apenas o formato de 5 dígitos — não há vínculo geográfico exato com o estado.

Exemplo de saída: 742 Oak Street / Austin, TX 78734 / United States

Portugal

O endereço português usa: tipo de via + nome, número na primeira linha, e código postal + localidade na segunda. O código postal português tem o formato NNNN-NNN (4 dígitos, hífen, 3 dígitos) e é gerenciado pelos CTT. O código gerado segue apenas o formato — não está vinculado ao distrito real.

Exemplo de saída: Rua da Liberdade, 18 / 1250-096 Lisboa / Portugal

Espanha

O endereço espanhol usa: tipo de via + nome + número na primeira linha, código postal + cidade na segunda e a província na terceira. O código postal espanhol tem 5 dígitos, com os dois primeiros indicando a província (01 a 52). Os dois primeiros dígitos gerados ficam nessa faixa, mas o código não é verificado na base de dados oficial.

Exemplo de saída: Calle Mayor 7 / 28013 Madrid / Madrid / España

Reino Unido

O endereço britânico usa: número + nome da via na primeira linha, a cidade na segunda e o postcode na terceira. O postcode britânico é alfanumérico com formato variado (ex.: SW1A 1AA, EC2V 8RF, M4 3AB), composto de área (letras) + distrito (dígitos), espaço, e sector + unidade (dígito + 2 letras). Os postcodes gerados seguem esse padrão visual mas não são validados na base do Royal Mail.

Exemplo de saída: 15 Victoria Street / London / SW1A 2JH / United Kingdom

Por que as cidades são reais mas os endereços são fictícios?

O objetivo desta ferramenta é gerar endereços verossímeis para testes de software. Cidades e estados reais garantem que os dados passem por validações de município/estado presentes em muitos sistemas. Por outro lado, é inviável gerar ruas e números reais offline sem uma base de dados oficial — que não é pública e gratuita para nenhum dos países suportados. Portanto:

  • Cidade e estado/região: reais, extraídos de datasets embutidos.
  • Logradouro (tipo + nome) e número: fictícios — combinações aleatórias plausíveis.
  • Bairro (apenas Brasil): fictício — nomes genéricos plausíveis.
  • Código postal: segue o formato do país, mas não é verificado em nenhuma base oficial.

Para que serve um gerador de endereço em testes de software?

  • Preencher formulários de cadastro em ambientes de desenvolvimento e QA sem expor dados reais.
  • Testar validações de campos obrigatórios, máscaras de código postal e selects de estado/cidade.
  • Popular bancos de dados de teste com registros variados de diferentes países.
  • Gerar dados para demonstrações de produto e mockups de interface internacionalizados.
  • Testar integrações com APIs de frete, logística e geolocalização com endereços de formato correto.
  • Validar formulários multilíngues e de endereço internacional sem usar dados reais de clientes.

Perguntas frequentes (FAQ)

Os endereços gerados existem de verdade?

Não. Apenas as cidades e os estados/regiões são reais. O logradouro, o número e o código postal são fictícios — gerados de forma aleatória dentro das regras de formato de cada país. Não use esses dados para correio real, cálculo de frete, cadastros oficiais ou qualquer finalidade além de testes de software.

Os códigos postais gerados são geograficamente corretos?

Não necessariamente. Eles seguem o formato do país (número de dígitos, presença de letras, separadores), mas não são vinculados ao estado ou cidade real. A única exceção parcial é o Brasil, onde o primeiro dígito do CEP é coerente com a macro-região do estado — mas os demais dígitos são aleatórios. Para EUA, Portugal, Espanha e Reino Unido, o código segue apenas o padrão visual do país.

Por que o CEP brasileiro tem um primeiro dígito coerente com o estado?

Os Correios dividem o país em 10 macro-regiões conforme o primeiro dígito do CEP (0 para Grande São Paulo, 9 para Rio Grande do Sul, etc.). Esta ferramenta respeita essa divisão para tornar o endereço mais verossímil — um endereço de Fortaleza nunca terá um CEP começando com 9 (que pertence ao RS). Os demais 7 dígitos são aleatórios.

Por que o ZIP Code dos EUA não é vinculado ao estado?

Seria necessária uma base de dados com as faixas de ZIP por estado, que não é pública e gratuita de forma completa. O ZIP gerado segue o formato de 5 dígitos, o que é suficiente para testar máscaras e validações de formato em formulários.

O postcode do Reino Unido segue o formato correto?

Segue o padrão visual: letras de área + dígitos de distrito, espaço, e dígito + 2 letras de unidade (ex.: SW3 4BK, EC1V 9NB). O Royal Mail usa variações específicas por região que não são replicáveis offline sem sua base de dados proprietária. O postcode gerado é suficiente para testar validações de formato.

Posso gerar vários endereços de uma vez?

Sim. Use o seletor de quantidade para gerar 1, 5 ou 10 endereços de uma só vez — todos do mesmo país e região selecionados. Útil para popular tabelas de teste com múltiplos registros rapidamente.

O que é o campo "complemento" e por que só aparece para o Brasil?

O complemento é uma informação opcional no endereço brasileiro que identifica a unidade dentro do imóvel (apartamento, sala, bloco, fundos etc.). Nos países anglófonos e ibéricos suportados, essa informação costuma fazer parte do número ou do nome da rua de outra forma, ou é omitida nos formatos mais comuns. Por simplicidade, o campo de complemento está disponível apenas para endereços brasileiros nesta versão.
